## 핵심 처리 시나리오

### 1. 작업지시 생성 및 동기화

ERP에서 작업지시를 생성한 뒤 MES API로 전송합니다.

MES는 작업지시 번호를 기준으로 기존 데이터를 확인하여, 동일한 요청이 재전송되더라도 작업지시가 중복 생성되지 않도록 처리합니다.

### 2. 버전을 이용한 변경 순서 보장

ERP에서 작업지시를 변경할 때마다 버전을 증가시킵니다.

MES는 현재 저장된 버전보다 높은 버전의 요청만 반영하여, 네트워크 지연으로 이전 요청이 뒤늦게 도착하더라도 최신 데이터가 과거 데이터로 덮어써지지 않도록 합니다.

### 3. 생산 상태에 따른 변경 통제

아직 생산이 시작되지 않은 작업지시는 최신 변경사항을 자동 반영합니다.

생산이 시작된 이후 수량, 납기일, 공정 정보 등 생산에 영향을 주는 변경 요청이 들어오면 즉시 반영하지 않고 승인 대기 상태로 저장합니다. 담당자는 요청 내용을 검토한 뒤 승인하거나 거부할 수 있습니다.

### 4. 변경 이력 관리

변경 요청의 이전 값과 요청 값을 기록하고, 승인·거부 여부와 처리 사유를 이력으로 관리합니다.

이를 통해 ERP의 요청이 MES에 어떻게 반영되었는지 추적할 수 있도록 합니다.

## 주요 처리 규칙

| 상황 | MES 처리 |
|---|---|
| 처음 수신한 작업지시 | 신규 생성 |
| 동일 작업지시·동일 버전 재수신 | 중복 반영 없이 기존 결과 반환 |
| 현재보다 낮은 버전 수신 | 이전 요청으로 판단하여 반영하지 않음 |
| 생산 시작 전 최신 버전 수신 | 자동 반영 |
| 생산 시작 후 주요 변경 수신 | 승인 대기 |
| 변경 요청 승인 | 작업지시 반영 및 이력 저장 |
| 변경 요청 거부 | 기존 작업지시 유지 및 거부 사유 저장 |
